# Heimerdinker V — VPGM Function-First Walkthrough M22

## Checkpoint

Make the post-Intake journey feel like a product doing useful work rather than
three pages explaining their own machinery. The connected slice is
Recommendations → Workshop → Match Deck.

## Workstreams

1. **Recommendations:** one acknowledgment, natural causal language, no raw
   intake-category collage, and one unmistakable primary continuation.
2. **Workshop:** show the member's actual working plan before explanatory or
   future-feature copy; make the next useful action obvious.
3. **Match Deck:** put the ranked people near the top, preserve the reasons and
   unknowns, and keep the long interpretive readout subordinate to the deck.
4. **Intake entry:** balance the opening composition and accept enough prose for
   a real company description without truncating it at a save boundary.

## Acceptance floor

- Intake's main project answer accepts 1,600 characters through UI and both
  local/account normalization boundaries.
- Recommendations says that the answers were used once, not three times.
- Recommendation reasoning does not quote raw category lists as if repetition
  were insight.
- Workshop is the primary next step after Recommendations; Match Deck is a
  clearly secondary alternative.
- Match Deck candidates render before the long current-read explanation.
- Desktop pages have no horizontal overflow, framework overlay, or console error.
