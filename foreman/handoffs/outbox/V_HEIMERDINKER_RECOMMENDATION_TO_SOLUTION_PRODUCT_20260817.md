# V — Recommendation to Solution Product

## Lane

Recommendations → concrete playbook → Bellows/tool/provider path → truthful profile evidence.

## Execution context

Local canonical Werkles repository on Betsy. Actual CBCC review precedes implementation.

## Allowed

- Inspect current Recommendations model, UI, and Bellows inventory.
- Dispatch and harvest exact existing Ender, Bean, and Computer/Thufir task routes.
- Build from returned review receipts.
- Implement at most three reviewed, local-only ideas.
- Add pure data contracts, member-facing UI, focused tests, and local browser proof.

## Forbidden

- Inventing providers, rankings, prices, availability, sponsorships, affiliate relationships, or professional claims.
- Provider calls, commercial outreach, spending, secrets, SQL/schema application, push, deploy, or production changes.
- Treating a packet in an outbox as cousin participation; only a returned receipt counts.

## Triple G

1. Replace generic next-action homework with a step-by-step option-specific playbook that produces a tangible member artifact.
2. Add a real Bellows learning/tool destination for the first useful recommendation path, reusing or honestly scaffolding existing content.
3. Establish a provider/resource comparison seam with explicit criteria, source/freshness fields, locality, and sponsorship/referral disclosure—local fixture only until researched and approved.

## Stop condition

The selected recommendation visibly offers a concrete working path and at least one useful artifact/content/resource bridge, all claims remain honest, and actual CBCC receipts plus focused/browser proof are on file—or an exact blocker is recorded.

## Momentum

After Triple G, inspect the next highest-leverage existing Bellows/content seam and implement at most two additional reviewed ideas within the same product contract. Pull receipts again before claiming CBCC completion.
