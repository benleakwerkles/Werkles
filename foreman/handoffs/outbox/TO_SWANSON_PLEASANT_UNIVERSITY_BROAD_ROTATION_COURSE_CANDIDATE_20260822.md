## Proposed course

**Broad Rotation Foremanship: Build the Whole Orchard Without Losing Custody**

This is not a request to ratify doctrine. Please critique, restructure, and
return a teachable course candidate with exercises and an examination. Preserve
source truth and reject anything that turns packet theater into teamwork.

## Learning objectives

A graduate should be able to:

1. Translate `VPGM` into visible work rather than a status answer.
2. Author a bounded Vision that names multiple product lanes and hard edges.
3. Pull cockpit truth and actual cousin state separately (`Double P`).
4. Distinguish packet written, dispatch attempted, response visible, harvested,
   validated, and assimilated.
5. Use actual CBCC judgment before claiming reviewed work; never rename a
   subagent or self-review as a cousin.
6. Execute the strongest cross-route ideas without climbing down after one
   apple (`Triple G`).
7. Run Momentum beats: re-pull, execute up to two new in-lane ideas, re-pull,
   and close with a receipt.
8. Preserve the Operator boundary: Ben is not the courier, Send button, reply
   hunter, browser-focus victim, password carrier, or routine confirmer.
9. Separate non-gate proof from real Human Gates involving authority, money,
   credentials, production data, public exposure, or irreversible action.
10. Walk the actual product and repair runtime, navigation, legibility, copy,
    persistence, and trust defects—not merely pass source tests.

## The broad-rotation loop

### V — author the checkpoint

Write a dated Vision card before work. Name three or more independent lanes,
the member outcome, proof required, and hard edges. V does not approve gates.

### P1 — cockpit pull

Read the canonical repository, branch, commit, dirty-tree truth, execution
context, current state, next action, human gates, lanes, budget, and company law.
Perform LOCAL HANDS READBACK before mutations.

### P2 — crew pull

Read the freshest packets and receipts for each actual assigned seat. A packet
in an outbox is not participation. A stale or unproved-custody response may
inform fact-checking but cannot be called a fresh review.

### G — build across lanes

Choose the strongest three source-bound ideas. At least two should be in
different product areas. For every candidate, state who or what controlled the
decision, what changed, what did not change, and what proves it.

### M — preserve momentum

After G: pull again. If there is no fresh packet, execute up to two new in-lane
ideas discovered by the build or walkthrough. Pull again. Then write the
receipt. M is recursive work discipline, not an excuse for endless wandering.

## Custody ladder

Teach this ladder explicitly:

`PACKET_WRITTEN` → `DISPATCHED` → `RESPONSE_VISIBLE` →
`RECEIPT_HARVESTED__NOT_VALIDATED` → `RECEIPT_VALIDATED` →
`READY_FOR_FOREMAN_ASSIMILATION` → `FOREMAN_ASSIMILATED`

Anything before terminal response and validation is transport state, not
review. The Foreman must say `route blocked` or `review owed` when that is true.

## Required anti-patterns

- answering an unrelated Operator question and calling that the VPGM;
- opening a cousin application and stopping;
- writing packets for every cousin, receiving none, and claiming teamwork;
- working alone for hours because routes were blocked;
- asking Ben to press Send, find replies, retype credentials, or reapprove
  routine work already in scope;
- changing one component repeatedly while Bellows, providers, copy, matching,
  and navigation remain idle;
- passing typecheck and skipping the rendered member journey;
- fixing one contrast defect while introducing a new navigation, persistence,
  custody, or copy defect elsewhere;
- taking foreground mouse or keyboard focus while the Operator is working;
- treating the Operator's last phrase as automatic product canon.

## Suggested practical exercise

Give the student a member-facing route with:

- a stale source test;
- one broken transition;
- one false persistence claim;
- one text-heavy dead stretch;
- one provider card that confuses scaffold with availability;
- two actual cousin routes, one returning and one blocked.

Require a Double-P/Triple-G/M pass. The student must build in at least three
lanes, assimilate only the real cousin response, preserve the blocker, repair
the local runtime if needed, and return one source contract plus one live-route
proof per slice.

## Examination rubric

Fail immediately for:

- invented review or custody;
- subagents presented as CBCC;
- unapproved provider/production/secret/schema/push action;
- Operator mueling;
- foreground-input theft;
- a readiness claim without candidate-bound proof.

Score the remaining work on:

1. scope breadth without drift;
2. source and account-custody truth;
3. member-visible value;
4. actual CBCC assimilation;
5. runtime and rendered proof;
6. clear receipts and next rotation;
7. ability to stop at a real gate without manufacturing one.
