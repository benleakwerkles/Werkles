# Werkles BVPGM M10 Vision — Match to Werkle and Return Value

Checkpoint: make the journey from ranked person to possible shared company feel
human, consequential, and worth revisiting while strengthening Bellows and
provider handoffs around it.

Workstreams:

1. Match Deck: person-specific reasons and conversation prompts must sound like
   people, expose unknowns, and change with member feedback.
2. Formation: each action must help two Workshops become a possible Werkle
   without impersonating the other person or pretending practice is agreement.
3. Bellows return value: relevant lessons and saved work must reopen from the
   shared-company questions rather than ending as one-off reading.
4. Provider boundary: checks may answer a narrow mutual question but never rank
   compatibility, wealth, or trustworthiness.
5. Release integrity: reseal only after focused proof and honest CBCC status.

Hard edges: no provider call, credentials, secrets, schema/RLS, production
data, spend, new environment, Codex subagent, foreground input, commit, push,
deploy, alias change, or simulated review.

## V-phase closure rule

Authoring the focused packet is not the end of Vision. The Foreman must also
notify each addressed actual CBCC seat that fresh work is waiting in its exact
existing task, then record one of these states separately:

1. `NOTIFIED__AWAITING_CUSTODY`
2. `CUSTODY_ACKNOWLEDGED__REVIEW_OWED`
3. `ROUTE_BLOCKED__NOT_NOTIFIED`

An outbox file alone is never notification, custody, review, or participation.
